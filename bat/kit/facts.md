# Facts about this repository

## Building and testing
- Whole suite: `cargo test`.
- One file: `cargo test --test integration_tests`. One test: `cargo test --test integration_tests -- --exact basic` (a bare name is a substring filter).
- Two `#[ignore]`d targets need their own run: `cargo test --test assets -- --ignored` and `cargo test --test system_wide_config -- --ignored` (needs `BAT_SYSTEM_CONFIG_PREFIX`).
- Every `tests/*.rs` is its own cargo target named after the file (`Cargo.toml` has no `[[test]]`); helpers are per-target `mod utils;` from `tests/utils/`. Unit tests are in-source `#[cfg(test)] mod tests`.
- CI lints hard: `cargo fmt -- --check`, `cargo clippy --locked --all-targets --all-features -- -D warnings`.

## Where things live
- `src/` — library; `src/bin/bat/` the binary, CLI in `clap_app.rs`
- `build/` — build script (`build = "build/main.rs"`; no `build.rs`)
- `assets/` — shipped data: `*.bin` blobs, syntax/theme submodules, `create.sh`
- `tests/` — integration targets, `examples/` fixtures, `syntax-tests/` harness

## Changing things together
- `clap_app.rs` help text -> regenerate `doc/long-help.txt` and `doc/short-help.txt`; `short_help`/`long_help` in `tests/integration_tests.rs` assert them with `expect_file!`.
- New CI job -> add it to `all-jobs: needs:` in `CICD.yml` too; `tests/github-actions.rs` asserts that list covers every other job except `winget`.
- New `syntax-tests/source/<L>/<f>` -> commit the `highlighted/<L>/<f>` twin, generated by `update.sh`, never by hand.
- Mappings are `.toml` under `src/syntax_mapping/builtins/<platform>/`; the Rust table is codegen'd into `OUT_DIR` by `build/syntax_mapping.rs`, `include!`d at `src/syntax_mapping/builtin.rs`.

## Traps
- Both help snapshots are `ignore`d on Windows and without the `git` feature: a stale one passes locally and fails in Linux CI.
- `tests/utils/command.rs` runs `bat` with `current_dir("tests/examples")` and strips 14 env vars (BAT_*, PAGER, LESSOPEN, NO_COLOR): fixture paths are relative to `tests/examples`.
- Syntaxes/themes are committed blobs `include_bytes!`d in `src/assets.rs`; editing a syntax submodule does nothing until `bash assets/create.sh` rebuilds them.
