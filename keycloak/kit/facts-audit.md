# How this fact sheet was built, and what was thrown away

The sheet beside this file is short on purpose. It was produced in three passes: one pass read
the repository and wrote down everything it believed; a second pass attacked every claim; a third
kept only what it could re-verify itself.

**44 facts kept, 8 dropped.** That ratio is the useful part of this page: facts about a
repository that cannot go stale are harder to produce than they look, and a sheet that is 40%
wrong is worse than no sheet, because an agent follows it.

- The admin console's English message bundle is machine-generated (it carries a do-not-edit marker). — The case-insensitive 'generated' grep that flagged js/apps/admin-ui/maven-resources/theme/keycloak.v2/admin/messages/messages_en.properties hits ordinary prose (`generatedAccessToken`, `hmacGenerated`, 'will be generated'), not a generator header. - Adding a new UI language requires adding it to the `locales=` list in the base themes' theme.properties files. — `grep -rn '^locales='` finds that list ONLY under themes/src/main/resources-community/, never under themes/src/main/resources/. docs/translation.md says to 'update the theme.properties files' but I could not verify the runtime consequence of omitting the locale, so I did not state a cause-and-effect rule.
- The server supports an `edb` (EnterpriseDB) database vendor, since test-framework/db-edb exists. — Wrong as drafted: quarkus/config-api/.../database/Database.java's `Vendor` enum has H2, MYSQL, TIDB, MARIADB, POSTGRES, MSSQL, ORACLE and `grep -rn edb -i` on it returns nothing; test-framework/docs/RUNNING_TESTS.md's list omits edb too. - tests/docs is a Maven module of the tests aggregator. — tests/pom.xml:34-43 lists only base, utils, utils-shared, custom-providers, custom-scripts, clustering, webauthn, conformance (plus migration-util behind `-Ptest-migration-util`). tests/docs is plain markdown.

## The cases beside this sheet, and the three passes they survived

The questions in `cases/` were drawn from the same reading of the repository, and then put
through three independent passes, each of which found what the one before it had let through.

**One** checked that every keyed path exists and belongs. It corrected keys and rejected nothing,
which is why there is a second: a check that refuses nothing cannot tell a good question from a
lenient reviewer.

**Two** was forced to state, for every question, the one sentence that says what makes a reply
right — and to name its three worst. It found questions whose "which single X" had eight valid
answers, keys that credited one of thirty-eight files carrying the same generated banner, and a
key that named a file as evidence of *absence*, which a correct reply cannot cite.

**Three** repaired the keys pass two judged incomplete, under one standing rule: a key is never
fitted to what an agent would find. Where a question was too broad to have a bounded answer, it
was narrowed rather than padded — and in one case it refuted pass two's complaint instead of
obeying it.

**12 of 12 candidates ship.** What was dropped, and why:

- candidate 5 — The key does not answer the question. The first clause asks where each English/other-language pair LIVES; docs/translation.md spells out six English sources and six -community directories, and the key contains none of them — it substitutes themes/src/main/resources-community/theme/base/login/theme.properties, a two-line `locales=` list that is not a translation pair. An agent that reads the repository and reports the messages_en.properties paths correctly scores zero on a third of the question, which is the exact failure mode described as worse than a spurious file. The remaining key (two js poms, themes/pom.xml, language-maintainers.yml) is also the half that one grep for 'community' produces.
- candidate 0 — Three riddles stapled together, and the third has no single answer: 38 files under saml-core-api/src/main/java/org/keycloak/dom carry the identical 'vhudson-jaxb-ri-2.1-661' banner and the key credits AlphabetType.java alone, so which of 38 the agent happens to cite decides its score. Worse, saml-core-api/pom.xml is keyed as evidence of ABSENCE — I confirmed it declares no generator plugin whatsoever — so a correct reply ('nothing in the build generates these any more') cannot name the file that proves it. The compound shape also means a reply that nails one of three parts looks like a failure.
- candidate 14 — Four sub-questions, eleven key files, and the clause that should carry the case is keyed by sampling. 'The aggregate entry points of each tree' is 13 @Suite classes in tests/base/.../suites plus base-suite.sh, suite.sh, suite-list-tests.sh and eight suite definitions under testsuite/.../testsuites; the key names 4 of those ~23. tests/migration-util is a 20-class Java rewriter represented by two shell scripts. And it re-tests candidate 1's subject — Base1/2/3TestSuite.java appear in both keys — so shipping both gives the new-tree suite fact two votes.

### What each shipped case cannot see

Every case has a weakness; a benchmark that claims otherwise is not being read carefully. These
are the ones the selection pass named for the questions that did ship.

- *Bumping this project's release version touches far more than the Maven coordinat…* — 'List every file it rewrites' is literally ~190 poms (versions:set -DartifactId=*) and the key carries only the root pom.xml, so the scope of the first half depends on the grader's charity about the phrase 'all poms'; and as in [7] the actual finding — the ENV/ARG mismatch — earns no key path of its own, so a wrong diagnosis with a right file list scores full marks.
- *A Maven plugin lives in this tree whose only purpose is to force every database …* — The punchline is not gradeable — 'what makes it a no-op' is the ABSENCE of the two JSON files, which cannot be a key path, so an agent that lists the plugin and the two poms but misses the silent no-op scores identically to one that nails it; the key also keys VerifyMojoTest.java, which the question never asks for, and omits AbstractMojo.java, where the two file parameters are actually declared.
- *Adding one user-visible server configuration option makes a family of byte-exact…* — The golden directory holds 22 approved.txt files and the key credits three of them (testStartHelp, testStartHelpAll, testBuildHelp); an agent that answers 'all 22 under approvals/cli/help/' by naming the directory, or that cites testStartDevHelpAll, is marked down for being right, and PropertyMappers registers groupings rather than individual mappers so the last sub-answer is slightly mis-aimed.
- *The current test framework finds its pluggable pieces through a service-loader c…* — The vendor-gap half rests on an absence in Database.java, which is cheap to assert and hard to verify, and the key credits three of db-edb's five source files — an agent that names the module plus EnterpriseDbTestDatabase.java and KeycloakEnterpriseDbContainer.java has identified the right module and still loses points; eighteen other modules also register the same service file, so the 'contract' half is easy.

### How completeness is scored

A key file whose basename appears in the question or anywhere in the sheet is struck off before
scoring, so the sheet can never be credited for handing over its own answer. That subset is
identical for both arms and is what the completeness figure in `RESULTS.md` is computed on.
